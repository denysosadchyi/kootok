# Патерн `context-aside` — основна колонка + бічний контекст

## Задача

Екрани, вузькі за природою (форма анкети, форма заявки, список чатів), на
десктопі не розтягуються на всю ширину контейнера сторінки і не лишають
порожнечі: поруч з основною колонкою стоїть контекст рішення — кімната, на
яку подається заявка, і шлях (кроки анкети, що буде після заявки).

## Поріг

3 сторінки з однаковою семантикою «дія + контекст»: «Анкета сумісності»,
«Заявка» (`lesson-6/`), «Чати» (`design-system/examples/chats.html`). Поріг
README (3) досягнуто.

## Склад

| Частина | Компоненти |
|---|---|
| Каркас | `kit-columns` > `kit-columns__main` + `kit-columns__aside` (`layout.css`) |
| Основна колонка | форма (`kit-page-intro`, `kit-progress`, `kit-step`/`kit-fieldset`, `kit-actions`) або `kit-card--list` з `kit-chat-list` |
| Контекст | `kit-conversation-context` (кімната; у бічній колонці — вертикальна картка, `chat.css`), `kit-card--section` з `kit-steps` (`progress.css`) |

## Розмітка

```html
<main class="kit-shell__body">
  <div class="kit-columns">
    <aside class="kit-columns__aside" aria-label="Кімната, на яку подаєш заявку">…</aside>
    <div class="kit-columns__main">…</div>
  </div>
  <p class="kit-footer">…</p>
</main>
```

## Правила

- **Десктоп (від `--bp-desktop`):** `minmax(0, 1fr)` + `--size-page-aside`,
  проміжок `--space-detail-column-gap` — та сама геометрія, що в
  `listing-detail`, тож бічна колонка стоїть на тому самому x на всіх екранах.
  Бічна колонка — sticky. В основній колонці дії — за вмістом від лівого
  краю; група з 2–3 радіо — у ряд.
- **Телефон і планшет:** одна колонка в порядку DOM. Контекст, без якого
  екран зрозумілий (кроки анкети вже передає прогрес), — `kit-columns__aside--wide`:
  лише у двох колонках. Контекст, потрібний завжди (кімната в заявці), стоїть
  у DOM першим і видимий на всіх ширинах.
- Бічна колонка не дублює основну: лише контекст і шлях, без головної дії.
- Анімацій немає.
