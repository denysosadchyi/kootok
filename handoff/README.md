# Хендофф — специфікація поведінки «Кутка»

Для розробника, який будує продукт за дизайном. Тут описано те, чого не видно
в статичних макетах: коли зʼявляється помилка, що вважається валідним, що
відбувається на порожньому списку, куди веде кожна дія.

**Правило: специфікація посилається, а не дублює.** Тут немає стилів, кольорів
і текстів інтерфейсу — лише посилання на компонент, стан, рядок копі й файл
поведінки. Якщо посилання і специфікація розходяться, правий код і копі, а
специфікацію треба виправити.

## Як читати посилання

| Посилання | Формат | Приклад |
|---|---|---|
| Компонент і стан | назва компонента → сторінка docs, якір | кнопка `button`, стан disabled → [`docs/button.html#states`](../design-system/docs/button.html#states) |
| Поведінка, вже реалізована в кіті | файл + «шапка» (коментар на початку файлу) | [`sheet.js`](../design-system/components/sheet.js), шапка, «Фільтрація стрічки» |
| Чинний текст (є на активному екрані) | ключ із [`microcopy.md`](microcopy.md), розділ «Активні екрани» | `listings.filter.empty` |
| Історичний текст (стан не намальований) | `microcopy.md › Повний інвентар › <файл стану> › <зона>` | `microcopy.md › Повний інвентар › listings-error.html › h4` |
| Тон тексту, якого ще немає | `voice.md › Правила за типом елемента › <тип>` | `voice.md › … › Помилка` |
| Вузол флоу | `flows.md › Flow N › «<вузол>»` | `flows.md › Flow 1 › «Чи є результати?»` |

**Про `microcopy.md`.** Тексти активних екранів мають стабільні ключі
`<екран>.<зона>.<елемент>` (розділ «Активні екрани»). Тексти станів, яких ще
немає на екранах, ключів не мають: посилання ведуть на розділ «Повний
інвентар», файл стану й зону. Це тексти станів із вайрфреймів уроку 4: вони
пройшли аудит, але не звірені з активним прототипом. Брати їх як чинний текст для
стану, якого ще немає на екрані, а перед релізом звірити з `voice.md`.

## Позначки статусу

- **[прототип]** — поведінку видно в активному прототипі (5 екранів:
  `lesson-6/listings`, `listing` + 4 `listing-<район>`, `compatibility-form`,
  `application` і [`design-system/examples/chats.html`](../design-system/examples/chats.html)).
- **[опис]** — макета немає; поведінка описана у `flows.md`, текст — в
  історичному інвентарі `microcopy.md`.
- **[трюк прототипу]** — так зроблено, щоб показати сценарій без бекенду; у
  продукті не відтворювати.
- **[відкрито]** — рішення не прийняте; номер веде в
  [`open-questions.md`](open-questions.md).
- **[дизайн-задача]** — потрібен новий дизайн або компонент, якого немає в кіті.

## Що не входить

Стилі, розміри й адаптив — у [`DESIGN.md`](../DESIGN.md) і
[`design-system/docs/`](../design-system/docs/index.html). Рух — у
`DESIGN.md › Анімація`. Курсова рамка (`course-nav.*`, `_base.css`) — не
продукт, її поведінку тут не описано.
