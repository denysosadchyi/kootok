# Agent workflow

- Кореневий агент коротко фіксує нову користувацьку правку в `IMPLEMENTATION_PLAN.md` як backlog item з owner і одразу делегує її; план не є блокуючим ритуалом для простих правок.
- Усі файлові правки в цьому проєкті виконує призначений агент. Кореневий агент не редагує реалізацію: він лише координує, делегує та перевіряє результат.
- Призначений агент об'єднує пов'язані дрібні правки в один batch і запускає один консолідований QA наприкінці batch, а не після кожної micro-change.
- Після делегування кореневий агент очікує статус призначеного агента, перевіряє один batch QA і тільки після успішної перевірки змінює статус вимоги на `done` та дає фінальний висновок.
- Накопичені вимоги не замінюються новою правкою: кожен активний пункт лишається в плані до окремого підтвердження виконання.
